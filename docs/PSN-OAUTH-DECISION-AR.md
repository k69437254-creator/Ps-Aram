# قرار تدفق PSN OAuth

**الحالة: مراجعة تكامل خارجية؛ لا توجد واجهة Sony عامة موثقة مثبتة لهذا التدفق ضمن المستودع.**

التطبيق الحالي يفتح صفحة Sony في متصفح النظام، ثم يطلب من المستخدم لصق رابط التحويل النهائي. يقوم `PsnAccountIdClient` بالتحقق من HTTPS والمضيف والمسار والمنفذ، ويرفض الخطأ وتكرار `code`، ثم يستبدل رمز التفويض ويحوّل `user_id` إلى Account-ID. يوضح المصدر أن نقاط النهاية وبيانات اعتماد العميل مقتبسة من تدفق Chiaki-NG المثبت وقد تتغير.

بيانات `CLIENT_ID` و`CLIENT_SECRET` المضمنة في APK هي بيانات عميل عامة قابلة للاستخراج؛ لا يجوز معاملتها كسر خادمي. لا يجوز نقلها إلى خادم وسيط غير معتمد، أو اختلاق PKCE/redirect URI/endpoint بديل، أو الادعاء بأن التدفق صار تلقائيًا دون مواصفات Sony موثوقة.

قبل أي تغيير سلوكي: احصل على عقد API أو وثيقة رسمية قابلة للتحقق من Sony/Chiaki upstream، ثم أضف اختبارات لحالات رفض التفويض، انتهاء/إعادة استخدام code، الروابط المزورة، وإغلاق الاتصال وعدم تخزين access token. إلى ذلك الحين يبقى التدفق اليدوي موضحًا بصدق ولا تُحفظ كلمة مرور المستخدم أو رموز OAuth في السجلات.
