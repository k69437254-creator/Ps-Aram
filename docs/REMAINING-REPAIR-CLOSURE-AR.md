# PS Link — حزمة إغلاق الإصلاحات البرمجية المتبقية

هذه الحزمة مخصصة للتطبيق بعد حزمة إصلاح مدة HLS الأولى، وبعد تطبيق الحزمة الثانية التي أُعدت لمسار Roku. خط الأساس الذي تتحقق منه هو الفرع `feature/platform-completion-pack` عند `79fe9bd3d22d4f1405e400def670f91cca5b7910`؛ لا تنفذ أي عملية Git للكتابة.

## الإصلاحات البرمجية التي تضيفها

1. **مسار Chiaki PCM إلى HLS:** يربط خرج PCM المفكوك من Chiaki بجسر داخل التطبيق ثم يشفره إلى AAC-LC عبر Android MediaCodec وينشره في HLS. مسار PCM الحالي إلى Android TV يبقى كما هو.
2. **مصدر صوت واحد:** ينتظر مسار Chiaki فترة قصيرة. إذا وصل PCM يُستخدم هذا المصدر؛ وإلا يبدأ Android Playback Capture كبديل عند توفر Android 10+ والإذن وسياسة المصدر. لا يُمزج المصدران في الجلسة نفسها. عند فشل ترميز PCM يحاول التحول إلى البديل.
3. **ترتيب PTS مشترك:** يمر صوت AAC وفيديو H.264 عبر طابور محدود بالعدد وبالذاكرة (16 MiB إجمالًا، و2 MiB كحد لكل وحدة)، ونافذة إعادة ترتيب 150ms. يبدأ بعد أول IDR، ويمنع إدخال الحزم التي وصلت خلف الطابع الزمني الذي تم الالتزام به أو تتجاوز حدود الذاكرة.
4. **ADTS ديناميكي:** يكوّن ناشر HLS رأس ADTS وفق معدل العينة وعدد القنوات الفعليين، بدل افتراض 48kHz/ستيريو لجميع مصادر الصوت.
5. **OCR:** يحسن دورة أخذ العينات إلى 350ms ويأخذ طابع الإطار الزمني بعد اكتمال PixelCopy، ويضيف عقد اختبار مصدرية.
6. **التحقق:** يضيف اختبارات Kotlin للطابور ورأس ADTS، واختبارات Python مصدرية تدخل في `scripts/check-source.sh`، وبالتالي في Android workflow الذي يشغل فحص المصدر.

## ما لا يمكن اعتباره مغلقًا بهذه الرقعة

- **TLS على كامل المسار:** لا يزال خادم الهاتف Ktor يعمل افتراضيًا عبر HTTP/WS محلي. تأمين المتصفح إلى reverse proxy لا يشفر الوصلة من الوكيل إلى الهاتف. لم أضف TLS ذاتيًا بشهادة غير موثوقة أو آلية تجاوز تحقق؛ ذلك يعطي أمانًا وهميًا ويكسر ثقة عملاء التلفاز. يلزم تصميم إصدار للشهادات/الثقة وتوزيع CA أو نفق داخلي مشفر واختباره على كل مستقبل قبل إغلاق هذا البند. لا تعرض المنفذ 8765 للإنترنت.
- **Roku:** الحزمة الثانية منفصلة؛ يلزم تطبيقها وفحص رقعتها ونتائجها. لا يعني وجود هذا الملف أن عميل Roku أصبح TLS تلقائيًا.
- **ترخيص `ara.traineddata`:** لا يمكن استنتاج الترخيص من الملف. بوابة الإصدار في `models/ARA-MODEL-RELEASE-GATE.md` تبقى مانعًا حتى توفر إثبات المنشأ والترخيص أو استبدال النموذج.
- **PSN/Sony:** تبقى صفحة Sony وتدفق نسخ رابط التحويل كما هو. بيانات اعتماد العميل المضمنة في APK عامة وقابلة للاستخراج وليست سرًا. لا يغير هذا الإصلاح واجهات Sony غير الموثقة ولا يخترع OAuth/PKCE غير مدعوم.
- **الأجهزة الفعلية:** لا يمكن إثبات التقاط صوت PS5 أو دقة OCR أو تشغيل Tizen/webOS/Roku/Xbox Edge أو توافق الترميزات بمجرد اختبارات المصدر. Xbox Edge مستقبل متصفح وليس تطبيق Xbox أصليًا.
- **انجراف A/V طويل المدى:** الطابور يعالج ترتيب وصول callbacks ضمن نافذة محدودة، لكنه لا يعوض قياس ساعة فك/تشغيل العتاد على جلسة طويلة. يجب قياس الانجراف فعليًا قبل إعلان التزامن المعتمد.

## تطبيق الحزمة

استخرج ZIP خارج المستودع، ثم طبّق الحزمتين الأولى والثانية، وبعدهما نفّذ:

```bash
bash /path/to/PS-Link-Remaining-Repairs-79fe9bd/apply.sh /root/PS-Link-Copilot
bash /path/to/PS-Link-Remaining-Repairs-79fe9bd/verify.sh /root/PS-Link-Copilot
```

يتحقق التطبيق من الفرع وHEAD وبصمات الملفات المستهدفة، ويشترط وجود إصلاح الحزمة الأولى. عند أي اختلاف غير متوقع يتوقف دون الكتابة. يغيّر ملفات الشيفرة والاختبارات المحددة فقط، ويستعيدها إن فشل التحقق. لا ينفذ `git add` أو `commit` أو `push` أو تبديل فرع أو reset أو clean أو stash.

## بوابة ما بعد التطبيق

نفّذ `bash scripts/check-source.sh`، ثم ارفع الحزم بعد موافقتك وشغّل GitHub Actions. يجب مراجعة `:mobile:testDebugUnitTest` وفحص HLS وبناء APKs في نتائج workflow. لا يُعلن النجاح قبل مراجعة نتائج CI، ولا تعني CI وحدها اجتياز اختبار جهاز فعلي.
