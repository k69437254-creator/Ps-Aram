# PS Link — Android Phone + Android TV

**ملف المصدر الموحد لمشروع PS Link.** يحتوي هذا المستودع على تطبيق الهاتف، وتطبيق Android TV المرافق، ونواة مشتركة لبروتوكول إرسال الترجمة، وسكربتات تجهيز محرك Chiaki-NG وبناء APKs عبر Gradle وGitHub Actions.

> **حالة هذا التسليم: Development Alpha / Source Package.** تم إعداد ملفات المشروع والتكامل والواجهات وسكربتات البناء، لكن لم يُنفّذ بناء Android فعلي أو اختبار على PS4/PS5 أو Android TV في بيئة الإنشاء الحالية؛ لذلك لا يصح وصفه بأنه إصدار إنتاجي خالٍ من الأخطاء. انظر قسم «ما يعمل وما لم يكتمل» أدناه.

## 1. بنية المنتج

مستودع واحد، وثلاث وحدات Gradle:

```text
PS-Link/
├── mobile/                  # APK الهاتف: com.pslink.app
├── tv/app/                  # APK التلفاز: com.pslink.tv
├── core/shared/             # بروتوكول الرسائل ومرشح تكرار النص
├── third_party/chiaki-ng/   # يُجلب من المصدر الرسمي عند bootstrap
├── models/                  # تعليمات حزم اللغات وسياسات النماذج
├── scripts/                 # bootstrap / prepare / build / validation
├── gradle/                  # Version Catalog
└── .github/workflows/       # بناء APK الهاتف والتلفاز تلقائيًا
```

### APKs

| التطبيق | Package ID | الغرض |
|---|---|---|
| PS Link Mobile | `com.pslink.app` | اكتشاف PlayStation والتسجيل وRemote Play والتحكم والترجمة وإرسال النص إلى التلفاز |
| PS Link TV | `com.pslink.tv` | استقبال النص المترجم وعرضه في تطبيق التلفاز |

يبقى مصدر Chiaki-NG ضمن الحزمة نفسها من منظور البناء: المشروع يحمّل نسخة مثبتة على commit محدد من المستودع الرسمي، ثم يربط ملفات Kotlin وموارد Android وCMake/JNI مباشرةً بوحدة الهاتف. لا يعاد تنفيذ بروتوكول Sony من الصفر.

## 3. ما تم تنفيذه في هذه الحزمة

### الهاتف

- استخدام تطبيق Android وطبقة JNI/CMake الأصليين من Chiaki-NG للاكتشاف والتسجيل وجلسات Remote Play والتحكم.
- إعادة تلوين الواجهة إلى أسود/أزرق وإضافة لوحة PS Link الرئيسية مع مدخل مترجم الألعاب.
- شاشة ترجمة عربية تتضمن اختيار لغة المصدر، إدخال نص يدوي، قراءة OCR من صورة يختارها المستخدم، ترجمة إلى العربية، وإرسال الترجمة إلى التلفاز.
- OCR محلي بمحركات ML Kit المضمّنة: Latin وJapanese وChinese وKorean.
- ترجمة على الجهاز عبر ML Kit Translation. يقوم المستخدم بتنزيل حزمة اللغة عبر Wi‑Fi؛ بعد اكتمال تنزيلها يمكن إجراء الترجمة محليًا دون اتصال.
- عميل WebSocket محلي مع رمز اقتران سداسي الأرقام لحماية جلسة الاستقبال من الأجهزة غير المقترنة داخل الشبكة.

### التلفاز

- تطبيق Android TV مستقل مع واجهة عرض كبيرة مناسبة لجهاز التحكم عن بعد.
- إنشاء رمز اقتران عند التشغيل وعرض عناوين IPv4 المحلية.
- خادم WebSocket يستقبل رسائل الترجمة على المنفذ `8765` والمسار `/subtitle`.
- عرض الترجمة والنص الأصلي في واجهة PS Link TV.
- إبقاء الشاشة مضاءة أثناء عرض الترجمة.

### النواة المشتركة

- بروتوكول JSON بإصدار `1` ورسائل مصادقة وترجمة محددة.
- حدود لطول النصوص المستقبلة لمنع رسائل ضخمة غير لازمة.
- `StableTextGate` لتصفية تكرار نتائج OCR عند ربط مصدر الإطارات مستقبلًا.

## 4. ما لم يكتمل بعد — مهم جدًا

لا أريد أن أوهمك بأن كل ما في التصور النهائي أصبح متصلًا بالفعل:

1. **OCR المباشر من بث Chiaki:** غير موصول في هذا الإصدار. شاشة OCR تقرأ لقطة شاشة يختارها المستخدم، أو نصًا يكتبه. واجهة Chiaki-NG الحالية تعرض الفيديو عبر Android `Surface` ولا تقدم في هذا الدمج callback جاهزًا لإطارات الفيديو إلى Kotlin. يلزم تعديل/توسعة مسار فك الترميز الأصلي في C/C++ لإخراج عينات إطارات آمنة دون تعطيل عرض Remote Play؛ ثم ربط ROI وdebounce بهذه العينات.
2. **ROI قابل للسحب فوق صورة اللعبة:** غير منفذ في واجهة هذه المرحلة.
3. **الترجمة المستمرة أثناء اللعب:** غير متاحة حتى يُنجز مسار استخراج الإطارات أعلاه.
4. **النص فوق HDMI:** تطبيق Android TV يعرض الترجمة داخل نافذته هو. لا يستطيع تطبيق Android TV عادي رسم طبقة فوق دخل HDMI القادم من PS4/PS5؛ ذلك يحتاج مسار فيديو/عتادًا وسيطًا مناسبًا.
5. **الاقتران التلقائي عبر QR:** هذه المرحلة تستخدم عنوان IP ورمزًا يدويًا من ستة أرقام؛ QR غير مضاف.
6. **اختبارات الأجهزة:** يجب اختبار الاكتشاف والتسجيل والـRemote Play وWake-up والتحكم والاتصال بالتلفاز على أجهزة فعلية؛ لا يمكن إثباتها بمجرد فحص ملفات المصدر.
7. **توقيع إصدار المتجر:** CI يبني Debug APKs. لم تُضف مفاتيح توقيع Release أو إعدادات النشر؛ لا ترفع Debug APK إلى المتجر كنسخة نهائية.

## 5. الترجمة دون اتصال وإدارة النماذج

المكتبة [`com.google.mlkit:translate:17.0.3`](https://developers.google.com/ml-kit/language/translation/android) تنفذ الترجمة على الجهاز. حزم اللغة لا تُضمّن مسبقًا في APK؛ ينزل التطبيق الحزمة عند طلب المستخدم عبر Wi‑Fi، ثم يستخدمها دون اتصال. حجم حزمة اللغة الواحدة يقارب 30 MB بحسب توثيق ML Kit، وقد يختلف. توثيق Google يذكر دعم أكثر من 50 لغة ويطلب إدارة تنزيل النماذج وحذف غير المستخدم منها.

**قيود الجودة والترخيص:** وثائق ML Kit تنبه إلى أن الترجمة بين لغتين غير الإنجليزية تمر عبر الإنجليزية، وقد يؤثر ذلك في الجودة. يجب تقييم أزواج اللغات المستخدمة فعليًا في الألعاب، خصوصًا اليابانية/الصينية/الكورية إلى العربية، قبل تقديم وعد تسويقي بدقة ترجمة احترافية. كما تنص إرشادات Google على عدم استخدام ML Kit Translation داخل تطبيقات الأجهزة المضمنة مثل التلفزيونات دون إذن كتابي مسبق؛ لذلك يقتصر محرك الترجمة في PS Link على تطبيق الهاتف، ويستقبل تطبيق التلفاز النص المترجم ويعرضه فقط.

OCR المضمّن يغطي حاليًا حروف Latin والصينية واليابانية والكورية ([توثيق تثبيت محركات OCR المضمّنة](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)). لا تتضمن هذه النسخة محرك OCR عربيًا، ولا تدّعي قراءة العربية من الصور.

راجع `models/README.md` قبل إضافة أي نموذج خارجي؛ لا تضمّن أوزانًا تجارية قبل التحقق من ترخيص إعادة التوزيع.

## 6. البناء عبر Termux وGitHub Actions

### المتطلبات على Termux

```bash
pkg update
pkg install git python unzip
```

فك ملف ZIP ثم ادخل مجلد المشروع. لا تحتاج إلى تثبيت Chiaki يدويًا؛ سكربت bootstrap يجلب المصدر المثبت:

```bash
cd PS-Link
bash scripts/bootstrap.sh
bash scripts/check-source.sh
```

هذا يجهز كود المصدر وGradle Wrapper. بناء تطبيق Chiaki الأصلي يحتاج Android SDK وNDK وCMake؛ لذلك أوصي بالبناء عبر GitHub Actions بدل محاولة تثبيت Android NDK كاملًا في Termux.

### رفع المستودع من Termux

أنشئ مستودع GitHub فارغًا أولًا، ثم نفّذ داخل مجلد PS-Link (استبدل الرابط برابط مستودعك):

```bash
git init
git branch -M main
git add .
git commit -m "Initialize PS Link Android project"
git remote add origin https://github.com/USERNAME/PS-Link.git
git push -u origin main
```

أو اختصر الخطوات بعد إنشاء المستودع الفارغ عبر: `bash scripts/push-github.sh https://github.com/USERNAME/PS-Link.git`

عند الدفع يبدأ Workflow الموجود في `.github/workflows/android.yml`، ويقوم بـ:

1. تثبيت JDK 17 وAndroid SDK.
2. تنزيل platform 35 وNDK `28.2.13676358` وCMake `3.22.1`.
3. جلب Chiaki-NG المثبت وجميع submodules.
4. فحص XML وملفات الحزمة.
5. بناء APK الهاتف وAPK التلفاز.
6. نشر الملفين كـGitHub Actions Artifact باسم `PS-Link-Android-APKs`.

### البناء محليًا بعد تجهيز SDK

```bash
./gradlew --no-daemon --stacktrace :mobile:assembleDebug :tv:app:assembleDebug
```

مخرجات البناء المتوقعة:

```text
mobile/build/outputs/apk/debug/mobile-debug.apk
tv/app/build/outputs/apk/debug/app-debug.apk
```

قد يختلف اسم APK قليلًا وفق إعدادات Gradle، لذلك Workflow يرفع كل ملفات APK الموجودة في مجلدي الإخراج.

## 7. التثبيت والاقتران

1. ثبّت APK الهاتف على Android Phone.
2. ثبّت APK التلفاز على Android TV.
3. افتح PS Link TV واترك الشاشة تعرض رمز الاقتران وعنوان IPv4.
4. افتح PS Link Mobile ثم مترجم الألعاب.
5. أدخل IP التلفاز والرمز الظاهر عليه واضغط «ربط التلفاز».
6. جرّب إدخال نص أو قراءة لقطة شاشة، نزّل نموذج اللغة عبر Wi‑Fi، ترجم النص، ثم أرسله إلى التلفاز.

الهاتف والتلفاز يجب أن يكونا على شبكة محلية واحدة، ويجب ألا يمنع الراوتر اتصال الأجهزة ببعضها (Client/AP isolation). الاتصال المحلي الحالي يستخدم `ws://` غير مشفر مع رمز اقتران قصير؛ استخدمه على شبكة منزلية موثوقة فقط. يلزم إضافة TLS/آلية مفاتيح أقوى قبل إطلاق تجاري واسع.

## 8. التراخيص والتوزيع التجاري

Chiaki-NG معلن بترخيص AGPL-3.0. هذا الترخيص لا يمنع البيع بحد ذاته، لكنه يفرض التزامات مهمة عند توزيع برنامج مشتق أو معدل، بما فيها إتاحة المصدر المقابل وفق شروط الرخصة. كما يحمل بعض ملفات upstream ترويسة `LicenseRef-AGPL-3.0-only-OpenSSL`؛ يجب مراجعة إشعارات كل المكونات والـsubmodules قبل إطلاق تجاري. لا أستطيع أن أصف هذا المشروع بأنه مغلق المصدر أو أؤكد توافقه القانوني التجاري دون مراجعة الترخيص والاعتماديات من مختص.

راجع `THIRD_PARTY_NOTICES.md` وملف `LICENSES/AGPL-3.0.txt` الذي ينشأ بعد bootstrap. المشروع مستقل وغير معتمد أو مصادق عليه من Sony Interactive Entertainment.

## 9. الخطوة الهندسية التالية

الأولوية التالية لإكمال وعد «الترجمة الحية أثناء Remote Play» هي تصميم patch أصلي صغير في مسار Chiaki video decoder يتيح frame callback إلى طبقة Kotlin مع backpressure، sampling معدل منخفض، وإيقاف OCR فور مغادرة جلسة اللعب. بعدها نضيف ROI، اختبار تأخير TTFT للترجمة، قياس RAM/الحرارة، واختبارات مزامنة الترجمة مع عرض التلفاز.
